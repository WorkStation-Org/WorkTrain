# ADR-0006 — สแกนใบหน้าด้วย AWS Rekognition ตอนเริ่มรอบเรียนและตอนเริ่มสอบ

วันที่ 25 ตุลาคม 2569 · สถานะ: ใช้อยู่ · ที่มา: grilling เรื่อง WorkTrain รุ่นที่ 1

ต้องกันสองอย่าง: **ฝากเพื่อนเรียน/สอบแทน** และ **เปิดจอทิ้งไว้** (แบบที่ระบบอบรมของบริษัทประกันภัยกัน)
**ตัดสินว่า** ลงทะเบียนใบหน้าครั้งแรกพร้อมยินยอม PDPA · สแกน (Face Liveness + CompareFaces · เทียบฝั่ง server)
ตอนเริ่มรอบเรียนและตอนเริ่มทุกครั้งที่สอบ · นิ่งเกิน 2 นาที = จบรอบ ต้องสแกนใหม่ · ไม่มีการสแกนกลางคัน

## เหตุผล

1. **ข้อสอบคือส่วนที่นับคะแนน** — สแกนแค่ตอนเริ่มเรียนแล้วให้เพื่อนสอบแทนได้ จึงต้องสแกนตอนเริ่มสอบด้วย
2. **จบรอบเมื่อนิ่ง แทนการขอสแกนกลางคัน** — ใช้หลักเดียวกับ "login ใหม่ = รอบใหม่" ไม่รบกวนคนที่อ่านอยู่จริง
3. **AWS กันได้ทั้งรูปถ่ายและการแก้ผลในเบราว์เซอร์** — Liveness กันยกรูป/จอมือถือมาส่อง · เทียบฝั่ง server ผลแก้ไม่ได้
   มีหน้าจอสแกนสำเร็จรูปสำหรับ React ไม่ต้องดูแลโมเดลเอง
4. **ต้นทุนต่ำเมื่อเทียบกับเวลาพัฒนา** — ≈ 0.55 บาทต่อการสแกน (60 คน ≈ 330 บาท/เดือน · 300 คน ≈ 1,650 บาท/เดือน)

## ไม่เลือก

- **ไม่ใช้ใบหน้า (จับความนิ่ง + LIFF อย่างเดียว)** — ผู้ตัดสินต้องการกันฝากเพื่อนให้ได้จริง
- **สุ่มสแกนเป็นระยะระหว่างเรียน** — รบกวนคนที่ตั้งใจเรียน ผลเท่ากับจบรอบเมื่อนิ่ง
- **ไลบรารีโอเพนซอร์สในเบราว์เซอร์ (Human · face-api)** — ฟรีแต่กันรูปถ่ายอ่อน และผลเทียบแก้ได้ ต้องหาที่รันเทียบฝั่ง server เอง
- **Azure Face** — ราคาใกล้กัน แต่ฟีเจอร์ยืนยันตัวตนน่าจะต้องขออนุมัติการใช้งานจาก Microsoft ก่อน (ยังไม่ยืนยัน)

## ผลที่ตามมา

- ใบหน้าเป็นข้อมูลชีวภาพ (PDPA มาตรา 26) — ต้องยินยอมชัดแจ้ง และหน้ายินยอมต้องบอกว่าส่งไปประมวลผลที่ AWS
- ต้องตรวจว่า Face Liveness มีใน region Singapore ก่อนเริ่ม (สำรอง Tokyo) และระบุที่ตั้งตามหลักฐาน (กติกาเครือข้อ 7)
- ต้องมีทางสำรอง: QR ไปสแกนบนมือถือ · TG ตรวจด้วยตาเมื่อไม่ผ่าน 3 ครั้ง · ลงทะเบียนใหม่ต้องให้ TG อนุมัติ
- ภาพสแกนเก็บใน R2 private 90 วันแล้วลบ
