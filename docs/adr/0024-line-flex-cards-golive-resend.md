# ADR-0024 — ข้อความ LINE เป็นการ์ด (Flex) · แจ้งการมอบที่ค้างถึงตัวจริงเมื่อเลิกช่วงทดสอบ

วันที่ 19 พฤศจิกายน 2569 · สถานะ: ใช้อยู่

เจ้าของจะเลิกช่วงทดสอบ (ลบ `TEST_LINE_GROUP_ID` ออกจาก Production) และขอให้ก่อนส่งถึงพนักงานจริง ข้อความเปลี่ยนจากข้อความล้วน
เป็นการ์ดที่อ่านง่าย · คนที่ได้รับมอบไประหว่างช่วงทดสอบ ข้อความ "ชุดการเรียนรู้ใหม่" ไปอยู่ในกลุ่ม Test และถูกบันทึกว่าส่งแล้ว จึงต้องได้รับแจ้งอีกครั้ง

**ตัดสินว่า**
- **ทุกข้อความที่ส่งผ่าน Work Bot เป็นการ์ด Flex** — ชุดใหม่ · ได้รับมอบอีกครั้ง · ไม่ต้องเรียนแล้ว · เตือนวันที่ 3/5 (ตัวต่อตัวและกลุ่มประจำตัว) ·
  สรุปเลยกำหนดถึงหัวหน้า · เวอร์ชันใหม่ · การอนุมัติ · แจ้ง TG (คิวใบหน้า · ด่านกันผังเพี้ยน)
- หน้าตาเดียวกันทุกใบ (`src/lib/line-cards.ts`): แถบหัวสีตามน้ำหนักเรื่อง (ดำ = ปกติ · น้ำตาล = เตือน · แดง = ยังไม่ผ่าน/เลยกำหนด ·
  เขียว = อนุมัติ · เทา = ไม่ต้องทำแล้ว) · กล่องต่อชุดมีชื่อชุดและกำหนดส่งแบบอ่านทันที (`พฤ. 26 พ.ย. · อีก 7 วัน`) · ปุ่มเดียวไป WorkTrain ·
  ชุดเดียวเปิดชุดนั้นตรง ๆ (`/learn/<assignmentId>`) · หลายชุดเปิดรายการของฉัน · เกิน 8 ชุดสรุปเป็น "และอีก n ชุด"
- สีมาจาก token ธีมสว่างของ `globals.css` (`--wt-*`) — LINE ไม่รู้จัก CSS variable · `flex.test.ts` ล้มเมื่อสีไม่ตรง
- **ทุกการ์ดมีข้อความล้วนคู่กันเสมอ** — เก็บลง `notifications.text` เหมือนเดิม · `altText` = บรรทัดแรก (ไม่มีลิงก์) ·
  ตรวจการ์ดด้วย `checkFlexMessage()` ก่อนส่งทุกครั้ง ไม่ผ่าน = ส่งข้อความล้วนแทนพร้อม log `flex_fallback_text`
  (GateWay ตอบ 202 ก่อนถึง LINE — การ์ดที่ LINE ปฏิเสธจะหายเงียบ · กติกาเครือข้อ 12) · ตัวตรวจยกมาจาก WorkDaily
- ส่งข้อความ "เวอร์ชันใหม่" ที่ล้มซ้ำ: สร้างการ์ดใหม่จากเวอร์ชันนั้น (`notifyNewVersion`) แทนการส่ง `notifications.text` เดิม
- **แจ้งซ้ำเมื่อเลิกช่วงทดสอบ** (`resendTestPeriodAssignments` ในรอบเช้า 09:00) — การมอบที่ยังเปิดอยู่ (ชุดใช้อยู่ · ยังไม่ผ่าน · ไม่ถูกตัดจบ ·
  ยังไม่เลยกำหนด · คนยังอยู่ในผัง) ซึ่งข้อความวันที่ 0 ถูกส่งเข้ากลุ่ม Test ได้การ์ด "ชุดการเรียนรู้ที่ต้องเรียน" ถึงตัวจริงครั้งเดียว รวมต่อคน
  - รู้ว่าเข้ากลุ่ม Test จาก `notifications.line_group_id` — ข้อความตัวต่อตัวลงค่านี้เฉพาะตอนส่งเข้ากลุ่ม Test
  - คีย์ `golive:<คีย์วันที่ 0>` · ยังตั้ง `TEST_LINE_GROUP_ID` อยู่ = ไม่ทำอะไร · ล้มแล้วรอบถัดไปลองใหม่ · ส่งครบแล้วไม่เหลืออะไรให้ส่ง (หยุดเอง)
  - เลยกำหนดแล้วไม่แจ้งซ้ำ — หัวหน้าได้สรุปเลยกำหนดทุกวันจันทร์อยู่แล้ว · เตือนวันที่ 3/5 ที่เคยเข้ากลุ่ม Test ไม่ส่งซ้ำ

## ไม่เลือก

- **ลบหรือเขียนทับแถว `notifications` ของช่วงทดสอบให้ระบบส่งใหม่เอง** — เสียหลักฐานว่าช่วงทดสอบส่งอะไรไป และกฎ `claim()` ไม่ให้จองแถวที่ `sent` ซ้ำโดยตั้งใจ
- **สคริปต์ส่งซ้ำรันจากเครื่อง** — key ของ GateWay ตั้งเฉพาะ Production ดึงลงเครื่องไม่ได้ · รอบเช้าบน Production ส่งได้และลองซ้ำเองเมื่อล้ม
- **ปุ่ม TG กดส่งซ้ำ** — ต้องมีหน้าใหม่สำหรับงานที่ทำครั้งเดียว · ลบ env แล้วรอบเช้าถัดไปส่งเองพอ
- **เก็บ JSON ของการ์ดลงฐาน** — ต้อง migration และการ์ดสร้างใหม่จากข้อมูลจริงได้เสมอ (ข้อความล้วนยังเก็บเป็นสำเนาเหมือนเดิม)
