# ADR-0017 — พักการสแกนใบหน้าไว้ชั่วคราว

วันที่ 16 พฤศจิกายน 2569 · สถานะ: ใช้อยู่

เจ้าของขอ "ปิดระบบสแกนหน้าไปก่อน" — ให้พนักงานเรียนและสอบได้ระหว่างที่การสแกนยังไม่พร้อมใช้ทั้งบริษัท
โดยเปิดกลับได้โดยไม่ต้องแก้โค้ด

**ตัดสินว่า**
- **สวิตช์เป็น env `FACE_SCAN_PAUSED=1`** (แบบเดียวกับ `TEST_LINE_GROUP_ID`) — ตั้งใน Vercel แล้ว redeploy · **ลบ env = กลับมาสแกนตามเดิมทันที**
- ระหว่างพัก `scanMode()` เป็น `paused`:
  - เริ่มรอบเรียนและครั้งที่สอบได้โดยไม่มีผลสแกน — แถวใน `study_sessions` / `attempts` มี `scan_id` ว่าง (migration 0015 เอา NOT NULL ออก)
    ด่านอยู่ที่ `scanGate()` ฝั่งเซิร์ฟเวอร์ ไม่ใช่ที่ปุ่ม · ไม่ได้พักแล้วส่ง `scanId: null` มา = "ต้องสแกนใบหน้าก่อน"
  - **ไม่บังคับยินยอม** — ความยินยอม (spec §8) เป็นเรื่องภาพใบหน้าอย่างเดียว ไม่มีการเก็บภาพก็ไม่มีอะไรต้องยินยอม ·
    กลับมาสแกนเมื่อไร คนที่ยังไม่ยินยอมจะถูกพาไป `/consent` เหมือนเดิม
  - ซ่อนเมนู "ใบหน้าของฉัน" · หน้า `/enroll` บอกว่าพักอยู่ ไม่มีปุ่มสแกน · หน้าแรกไม่ขึ้นแถบยินยอม/ลงทะเบียน
  - ยังมีอยู่ครบ: รอบเรียนนิ่ง 2 นาทีจบ · อ่านครบก่อนสอบ · ทีละข้อ · ออกจากหน้าสอบ 5 ครั้ง · หน้า TG `/admin/faces` (คิวเดิม)
- ผลสแกนที่ส่งมาระหว่างพัก (เช่น TG ยืนยันไว้ก่อน) ยังถูกตรวจตามเดิม — พักแค่ "ไม่ต้องมี" ไม่ใช่ "ไม่ตรวจ"

**ผลที่ตามมา**
- ครั้งที่สอบที่ `scan_id` ว่าง = สอบตอนพัก ไม่มีหลักฐานว่าเป็นตัวจริง — ถ้าต้องแยกในรายงานภายหลังให้กรองจากคอลัมน์นี้
- unique index ของ `scan_id` ยังกันผลสแกนเดียวใช้สองครั้ง (ค่าว่างซ้ำกันได้ใน Postgres)

## ไม่เลือก

- **ปุ่มเปิด/ปิดในหน้า TG** — ต้องมีตารางตั้งค่าใหม่และประวัติว่าใครกด · ยังไม่มีใครขอ และ env เปิดกลับได้ในไม่กี่นาที
- **บันทึกผลสแกนปลอมว่า "ผ่าน"** — ทำให้ข้อมูลโกหก แยกไม่ออกว่าครั้งไหนสแกนจริง
- **ตั้งให้ `off` (ไม่ได้ตั้ง AWS) ปล่อยผ่านแทน** — ลืมตั้ง AWS บน production แล้วระบบปล่อยผ่านเงียบ ๆ อันตรายกว่าสวิตช์ที่ตั้งใจเปิด
