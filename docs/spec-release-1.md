## 0. ภาพรวม

โจทย์ตั้งต้น: PD ออก Collection ใหม่พร้อม Pricelist + เงื่อนไขการขาย → TG นำเข้าระบบ →

TG ติดตามให้ครบ และดูสถิติเพื่อให้รางวัลประจำเดือน (นอกระบบ)

ระบบทำให้กว้างกว่าโจทย์: **ใช้ได้ทุกแผนก** — PD เป็นผู้สร้างกรณีหนึ่ง Sales Manager ออกข้อสอบให้เซลเป็นอีกกรณี
และพ่วงกับ Onboarding ของ WorkHR

- **เขียนใหม่ทั้งหมด** ใน repo นี้ (ADR-0001) — โค้ดรุ่นเก่า (Prisma · login Entra ตรง · ตำแหน่ง/กลุ่มของตัวเอง) ไม่มีผู้ใช้และไม่มีข้อมูล ไม่ต้องย้าย
- Stack เดียวกับพี่น้อง (WorkHR · WorkDaily): Next.js + Drizzle + Neon (Singapore) · vitest + PGlite
- ตามกติกาเครือ (`WS-Strategy/MASTER-ARCHITECTURE.md` §2):
  login ผ่าน **WorkID SSO** (ข้อ 4) · ส่ง LINE/Email ผ่าน **WorkGateWay** เท่านั้น (ข้อ 5) ·
  `GET /api/health` ที่แตะ dependency จริง (ข้อ 6) · consent PDPA ตั้งแต่วันแรก (ข้อ 8) · เข้า `main` ผ่าน PR (ข้อ 9) ·

เวอร์ชัน · การอ่านและการสอบพร้อมสแกนใบหน้า · การตามแบบไล่ระดับ · Dashboard + Leaderboard · API ให้ WorkHR

**ไม่อยู่ในระบบ:** การจ่ายรางวัล (ADR-0007) · ทะเบียนคน/ทีม/ตำแหน่ง (ADR-0002)

## 1. บทบาทและการเข้าระบบ

- Login ผ่าน WorkID SSO ด้วย app key `worktrain` ตาม `WorkID/docs/INTEGRATE-SSO.md` — ไม่มี credential ของตัวเอง
- เข้าจากปุ่มใน LINE (LIFF) ได้ด้วย ตามแบบ WorkHR ADR-0007 — WorkID ยืนยันว่าเป็นเครื่อง LINE ของเจ้าตัว
- proxy ถาม `/api/v1/session/check` เป็นระยะ — HR กดพ้นสภาพ = หลุดทันที และไม่ถูกนับเป็นคนค้าง
- role ของแอป `worktrain` ที่ WorkID:

| role | ใคร | ทำอะไรได้ |
|---|---|---|
| `admin` | TG | ทุกอย่าง · เห็นทุกคน · ตั้งเส้นทาง Onboarding · ตรวจภาพสแกน · อนุมัติลงทะเบียนใบหน้าใหม่ |
| `author` | PD · Sales Manager · ฯลฯ | สร้างชุดการเรียนรู้ · เห็นผลของชุดที่ตัวเองสร้าง |
| `user` | ทุกคน (`default_role`) | เรียน · สอบ · เห็นสถิติของตัวเอง + Leaderboard |

- ผู้อนุมัติไม่ใช่ role — เป็นคนที่ถูกระบุในชุดการเรียนรู้นั้น
- หัวหน้าเห็นสถิติของทีมที่ตัวเองดูแล จาก `managedTeamIds` ใน `/v1/org` — ไม่ต้องมี role เพิ่ม

## 2. ชุดการเรียนรู้

- ผู้สร้างตั้ง: ชื่อ · เอกสารต้นทาง · แม่แบบข้อสอบ · ผู้รับ · กำหนดส่ง (ค่าเริ่มต้น 7 วัน) · เวลาสอบ (ค่าเริ่มต้น 15 นาที) · ผู้อนุมัติ
- **ชุดสินค้า (PD):** 1 ชุด = 1 Collection
  - **แคตตาล็อก** = PDF ที่ PD ทำอยู่แล้ว (เป็นภาพทั้งเล่ม ไม่มีชั้นข้อความ — ตรวจจาก Signature V.1 และ Progetto V.3)
    ใช้ทั้งให้ผู้เรียนอ่านและให้ AI อ่านจากภาพ
  - **Pricelist** = ไฟล์ที่ PD มีอยู่แล้ว (รอตัวอย่าง — §14) ใช้เป็นที่มาของราคาและเงื่อนไขการขาย
- **ชุดทั่วไป:** เอกสารอะไรก็ได้ (PDF · PPT · Excel · วิดีโอ · ลิงก์) + ข้อความ
- สถานะ: ร่าง → รออนุมัติ → (ตีกลับ → ร่าง) → ใช้อยู่ → ปิด

## 3. ข้อสอบจาก AI

- ใช้ Claude ผ่าน `@anthropic-ai/sdk` (ตัวเดียวกับ WorkDaily)
- ออก **5 ชุดข้อสอบ ชุดละ 10 ข้อ** ปรนัย 4 ตัวเลือก (ADR-0003) — ทั้ง 5 ชุดใช้สัดส่วนเดียวกัน
- แม่แบบ **สินค้าใหม่ (PD)** (ค่าเริ่มต้นของชุดสินค้า):

| หัวข้อ | ข้อ |
|---|---|
| Spec / ขนาด / รุ่น | 3 |
| ราคา / เงื่อนไขการขาย | 3 |
| วัสดุ / มาตรฐาน / จุดขาย | 2 |
| การจับคู่สินค้า (Signature Pairing) / สถานการณ์ขาย | 2 |

- แม่แบบ **ทั่วไป**: AI กระจายให้ครอบคลุมทุกหัวข้อของเอกสาร
- ทุกแม่แบบแบ่งระดับ **จำ 4 · เข้าใจ 4 · สถานการณ์ 2** — ผู้สร้างปรับสัดส่วนได้
- ทุกข้อ AI ต้องระบุ**ที่มา** (หน้าของแคตตาล็อก หรือแถว/คอลัมน์ของ Pricelist)
- ข้อที่เป็นตัวเลขราคา: ระบบเทียบคำตอบกับ Pricelist เอง — ไม่ตรง = ติดธงให้ผู้อนุมัติเห็น ไม่ซ่อน

## 4. การอนุมัติ

- ผู้อนุมัติค่าเริ่มต้น = หัวหน้าตามผัง WorkID ของผู้สร้าง (`managerPersonId`) · ผู้สร้างเปลี่ยนเป็นรายชุดได้ (ADR-0004)
- ผู้อนุมัติทำได้สามอย่าง:
  1. **แก้เอง** — คำถาม · ตัวเลือก · เฉลย
  2. **ให้ AI ออกใหม่ทีละข้อ** — ได้ข้อใหม่หัวข้อและระดับเดิม
  3. **ตีกลับพร้อมความเห็น** — เมื่อต้นทางผิด (Pricelist ผิด · แคตตาล็อกผิด) ผู้สร้างแก้ไฟล์แล้วออกข้อสอบใหม่
- อนุมัติแล้ว = ส่งให้ผู้รับทันที
- ทุกการแก้เก็บประวัติ: ใคร · เมื่อไร · ข้อไหน · ก่อน/หลัง

## 5. ผู้รับและการมอบ

- ข้อมูลคน ทีม ตำแหน่ง หัวหน้า มาจาก WorkID `/v1/org` (ต้นทางจริงคือ WorkHR) — WorkTrain ไม่เก็บทะเบียนเอง (ADR-0002)
- ผู้สร้างเลือกผู้รับด้วยเงื่อนไขผสมกันได้:
  - ตามตำแหน่ง — "ผบ ทั้งหมด" · "Mgr ทั้งหมด"
  - ตามทีม — ทีมขายและการตลาด (Sales · Spe · Designer · CRM) · ทีม PD และ PS
  - คนที่ดูแลทีม — หัวหน้าทีมย่อยจัดส่งทั้งหมด · หัวหน้าทีม QC
  - กลุ่มเฉพาะกิจ
- หน้าเลือกผู้รับแสดงรายชื่อจริงก่อนกดส่ง
- เงื่อนไขเก็บไว้ ไม่ใช่แค่รายชื่อ — คนที่เข้าตำแหน่ง/ทีมนั้นระหว่างที่ชุดยังใช้อยู่ได้รับมอบด้วย โดยกำหนดส่งนับจากวันที่ได้รับมอบ
- คนที่พ้นสภาพ: การมอบค้างไว้ ไม่นับเป็นคนค้าง

## 6. เส้นทาง Onboarding และ WorkHR

- TG ผูกชุดการเรียนรู้เข้ากับตำแหน่ง (ADR-0005)
- คนใหม่ใน WorkID หรือคนที่ย้ายตำแหน่ง → ได้รับมอบชุดของตำแหน่งนั้นอัตโนมัติ (ตรวจจาก sync `/v1/org`)
- คนใหม่ยังไม่มีอีเมลตอนที่ใบ checklist ของ WorkHR เปิด — การมอบเกิดเมื่อมีตัวตนใน WorkID แล้วเท่านั้น
- WorkTrain เปิด API ให้ WorkHR ดึงสถานะ:
  `GET /api/v1/people/{email}/training-status` → แต่ละชุดในเส้นทาง: ได้รับมอบเมื่อไร · ผ่านแล้วหรือยัง · ผ่านเมื่อไร
  — ต้องมี API key (consumer) แบบเดียวกับ WorkID
- ข้อใน checklist ของ WorkHR ("ผ่าน training พื้นฐาน") ติ๊กเองจาก API นี้ — งานฝั่ง WorkHR ไม่อยู่ใน repo นี้

### 6.1 รหัสตำแหน่ง (ต้องมีก่อนเปิดเส้นทาง Onboarding)

เส้นทาง Onboarding และการเลือกผู้รับตามตำแหน่ง **อ้างตำแหน่งด้วยรหัส ไม่ใช่ชื่อ** — ชื่อตำแหน่งแก้ได้ ถ้าผูกด้วยชื่อ
แก้ชื่อทีหลังคนในตำแหน่งนั้นจะหลุดจากเส้นทางเงียบ ๆ

ของที่มีวันนี้ (ตรวจโค้ด 25 ต.ค. 2569):
- WorkHR มีทะเบียน `positions` (รหัส integer ของ WorkHR) และการจ้างอ้าง `position_id`
- WorkID เก็บแค่ `persons.title` เป็นข้อความ · WorkHR ส่งแค่ `title` ใน `PUT /api/v1/hr/people/{email}` · `/v1/org` ให้แค่ `title`

ที่ต้องเพิ่ม (งานใน repo WorkHR และ WorkID ไม่ใช่ที่นี่):
1. WorkHR ส่ง `positionId` (รหัสตำแหน่งของ WorkHR) คู่กับ `title` ใน `PUT /api/v1/hr/people/{email}`
2. WorkID เก็บ `positionId` และเปิดใน `/v1/org` · `/v1/people*` คู่กับ `title` (ช่องที่เพิ่มทีหลัง — แอปเก่าถือว่าไม่มา = `null`)
3. แคตตาล็อกตำแหน่ง (รหัส + ชื่อ + active) ให้ TG เลือกตอนผูกเส้นทาง — WorkID เปิด หรือ WorkHR เปิดเอง ให้เจ้าของสองระบบตัดสิน

ระหว่างที่ยังไม่มี: WorkTrain ไม่เปิดเส้นทาง Onboarding และการเลือกผู้รับตามตำแหน่ง · ใช้ตามทีม · คนที่ดูแลทีม · กลุ่มเฉพาะกิจไปก่อน

## 7. เวอร์ชันของเอกสารต้นทาง

- ผู้สร้างอัปโหลดเวอร์ชันใหม่ → ระบบให้ AI สรุปว่าเปลี่ยนอะไรเทียบกับเวอร์ชันเดิม
- ผู้อนุมัติเลือก (ADR-0008):
  - **เปลี่ยนเล็ก** (ราคาบางรุ่น · แก้คำผิด) → ผู้เรียนที่ผ่านแล้วอ่านส่วนที่เปลี่ยนแล้วกด "รับทราบ" ไม่ต้องสอบ
  - **เปลี่ยนใหญ่** (Series ใหม่ · เงื่อนไขการขายเปลี่ยน) → AI ออกข้อสอบเฉพาะส่วนที่เปลี่ยน (~5 ข้อ) ผ่านการอนุมัติเหมือนเดิม
    ผู้เรียนที่ผ่านแล้วต้องสอบส่วนนี้ · คนที่ยังไม่ผ่านสอบชุดเต็มของเวอร์ชันใหม่
- ข้อสอบ 5 ชุดของเวอร์ชันใหม่ต้องอัปเดตให้ตรงเอกสารด้วย ไม่งั้นคนที่ยังไม่ผ่านจะสอบจากข้อมูลเก่า

## 8. การยืนยันตัวตน (สแกนใบหน้า)

- **ลงทะเบียนใบหน้า** ครั้งแรก พร้อมหน้ายินยอม PDPA (ข้อมูลชีวภาพ — มาตรา 26) ที่บอก: เก็บอะไร · ส่งไปประมวลผลที่ AWS · เก็บนานเท่าไร · ใครเห็น
- สแกนด้วย **AWS Rekognition**: Face Liveness + CompareFaces · เทียบที่ฝั่ง server (ADR-0006)
- สแกน 2 จังหวะ: **เริ่มรอบเรียน** และ **เริ่มครั้งที่สอบ** (ทุกครั้ง รวมสอบซ้ำ) — ไม่มีการสแกนกลางคัน
- เครื่องไม่มีกล้อง → หน้าจอแสดง QR → สแกนบนมือถือผ่าน LINE → เครื่องคอมไปต่อเอง
- เทียบไม่ผ่าน 3 ครั้งติด → เก็บภาพทั้ง 3 ส่งคำขอให้ TG ตรวจด้วยตา (ยืนยัน / ปฏิเสธ) · ระหว่างรอ อ่านได้ สอบไม่ได้
- เทียบไม่ผ่านบ่อย (เกิน 3 รอบต่อเดือน) → แนะนำลงทะเบียนใหม่ · TG ต้องอนุมัติ (กันการลงทะเบียนหน้าคนอื่นแทน)
- ภาพจากการสแกนเก็บใน R2 แบบ private **90 วัน** แล้วลบเอง · ใบหน้าที่ลงทะเบียนเก็บจนพ้นสภาพ
- **การยินยอมเป็นเงื่อนไขของการใช้แอป** — ไม่ยินยอม = ใช้ WorkTrain ไม่ได้ ไม่มีทางเลือกอื่น (เป็นแอปภายในที่บริษัทบังคับใช้ได้)
  หน้ายินยอมขึ้นตั้งแต่ login ครั้งแรก ก่อนเห็นอะไรในระบบ · ถอนความยินยอม = ลบใบหน้าที่ลงทะเบียน และใช้แอปไม่ได้จนกว่าจะยินยอมใหม่
  · คนที่ยังไม่ยินยอมนับเป็นคนค้างตามปกติ และขึ้นให้ TG เห็นแยก
- ฐานทางกฎหมายของการบังคับยินยอม HR / กฎหมายต้องรับรอง (§14) — PDPA ถือว่าความยินยอมที่เป็นเงื่อนไขของงานอาจไม่ใช่ความยินยอมโดยอิสระ

## 9. การเรียน

- รอบเรียนเริ่มด้วยการสแกน · จบเมื่อออกจากระบบ · **นิ่งเกิน 2 นาที** (ไม่มีเลื่อน/เมาส์/แตะ) · session หมดอายุ
- login ใหม่ = รอบใหม่ = สแกนใหม่ · ความคืบหน้าการอ่านยังอยู่
- นับเวลาอ่านเฉพาะตอนที่แท็บอยู่หน้า — สลับแท็บ/ย่อจอ = หยุดนับ
- ต้อง**เลื่อนผ่านเอกสารครบทุกหน้า** — แคตตาล็อกแสดงในระบบทีละหน้า ไม่ใช่แค่กดเปิดไฟล์
- **คำถามแทรก** ระหว่างอ่าน (AI ออกจากหน้านั้น) — ตอบผิดต้องอ่านหน้านั้นซ้ำ ไม่นับคะแนน
- ต้องอ่านครบทุกเอกสารก่อนจึงเริ่มสอบได้

## 10. การสอบ

- จำกัดเวลา 15 นาทีต่อครั้ง (ผู้สร้างแก้ได้) · หมดเวลา = ส่งเอง ข้อที่ไม่ตอบ = ผิด
- สุ่ม 1 ใน 5 ชุดข้อสอบ ไม่ซ้ำกับครั้งก่อนจนกว่าจะครบ 5 ชุด · สลับลำดับข้อและตัวเลือกทุกครั้ง
- แสดงทีละข้อ ย้อนกลับไม่ได้
- ล็อกเอกสารต้นทางระหว่างสอบ
- ออกจากหน้าสอบ (สลับแท็บ/ย่อจอ): ครั้งที่ 1–4 เตือน · **ครั้งที่ 5 ส่งเอง** — นับเป็นครั้งที่สอบ · บันทึกทุกครั้งให้ TG เห็น
- ผ่าน = **80%** · สอบซ้ำได้ไม่จำกัด
- **ไม่ผ่าน 2 ครั้งติด** → ล็อกการสอบจนกว่าจะอ่านเอกสารใหม่ (forced re-learn)
- หลังส่ง: แสดงคะแนนและข้อที่ผิด **ไม่เฉลยคำตอบที่ถูก** (ADR-0009)

## 11. การแจ้งเตือนและการตาม

ทุกข้อความส่งผ่าน WorkGateWay · ปลายทาง LINE จาก WorkID (ส่งทุกเครื่องที่ `reachable` · `lineGroupId` ของกลุ่มประจำตัว)

| เมื่อ | ถึงใคร | ช่องทาง |
|---|---|---|
| ส่งขออนุมัติ / ตีกลับ | ผู้อนุมัติ / ผู้สร้าง | LINE รายคน |
| วันที่ 0 (อนุมัติ หรือได้รับมอบ) | ผู้เรียน | LINE รายคน + ลิงก์ LIFF |
| วันที่ 3 ถ้ายังไม่เริ่ม | ผู้เรียน | LINE รายคน |
| วันที่ 5 ถ้ายังไม่ผ่าน | ผู้เรียน + หัวหน้า | กลุ่ม LINE ประจำตัว (`lineGroupId`) |
| เลยกำหนดส่ง | TG + หัวหน้าแต่ละทีม | สรุปทุกเช้าวันจันทร์ |
| สแกนไม่ผ่าน 3 ครั้ง / ขอลงทะเบียนใหม่ | TG | LINE |
| เวอร์ชันใหม่ | ผู้เรียนที่ผ่านแล้ว | LINE รายคน |

- รวมข้อความตาม `lineGroupId` ก่อนส่ง — หัวหน้าคนเดียวใช้กลุ่มเดียวกับลูกทีมหลายคนได้
- ส่งไม่ถึง = ไม่นับว่าแจ้งแล้ว และขึ้นให้ TG เห็น

## 13. การป้องกันข้อมูลรั่ว

- ไฟล์ทั้งหมดอยู่ใน R2 แบบ private · เปิดด้วย presigned URL อายุสั้น หลังตรวจสิทธิ์ — ไม่มี public URL (ADR-0010)
- bucket `worktrain` (บัญชี Cloudflare เดียวกับระบบอื่น · token อ่าน/เขียนเฉพาะ bucket นี้) แบ่ง key ตามอายุข้อมูล:
  `sets/<setId>/v<version>/…` เอกสารต้นทาง · `faces/enroll/<personId>/…` ใบหน้าที่ลงทะเบียน (เก็บจนถูกแทน) ·
  `faces/scan/<personId>/…` ภาพสแกน — cron เช้าลบเมื่อครบ 90 วัน และ lifecycle rule ของ R2 ลบ `faces/scan/` ที่อายุเกิน 91 วันซ้ำอีกชั้น
- CORS ของ bucket: origin `https://worktrain.workstationoffice.com` · `GET` `PUT` `HEAD` · header `content-type` `range`
- แคตตาล็อกดาวน์โหลดได้ (ใช้ขายอยู่แล้ว) · **Pricelist ดูในระบบเท่านั้น** ไม่มีปุ่มดาวน์โหลด
- Pricelist ทุกหน้ามีลายน้ำ: ชื่อ + รหัสพนักงาน + วันเวลาที่เปิด
- Log ทุกการเปิดเอกสารต้นทาง: ใคร · ไฟล์ไหน · เมื่อไร
